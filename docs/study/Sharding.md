## Sharding(샤딩)
샤딩은 데이터를 여러 개의 독립적인 데이터베이스 서버(샤드)에 분산 저장하는 기법
본질적으로는 수평 파티셔닝을 여러 물리 서버에 걸쳐 적용한 것이라고 볼 수 있다.
각 샤드는 독립적인 DB 인스턴스이고, 전체 데이터의 일부만 가지고 있는다.

 예시) 유저 ID가 1~100만인 사용자는 shard A에, 100만~200만은 샤드B에 저장하는 식이다.
분산 방식으로는 Hash기반(샤드 키를 해싱해서 배정),Range 기반(범위별 배정), Directory기반(별도 매핑 테이블로 관리)등이 있다.

샤딩의 가장 큰 목적은 **스케일 아웃(수평 확장)**이다, 
단일 서버의 저장 용량, CPU, 메모리, 커넥션 한계를 넘어설 수 있고, 부하가 여러 서버로 분산된다.

단점이 생각보다 커서 도입 시 신중해야 된다.
- 샤드 간 조인이 사실상 불가능하거나 매우 비싸다.
- 트랜잭션을 여러 샤드에 걸쳐 보장하기 어렵다.
- 특정 샤드에 데이터가 몰리는 핫스팟 문제
- 샤드 추가 시 리밸런싱(재분배) 비용 등이 대표적이다.
