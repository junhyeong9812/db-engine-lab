# yield란?
sequence {} 블록 안에서 "값 하나를 내보내고, 그 자리에서 실행을  멈추는" 함수이다. 핵심은 값을 내보내는 것보다 멈춘다는 쪽이다.

일반 함수와 비교해보면,
```java
// 일반 함수: 리스트를 전부 만들어 한번에 반환, 실행이 끝까지 달린다.
fun numbers(): List<Int> {
    val list = mutableListOf<Int>()
    list.add(1)
    list.add(2)
    list.add(3)
    return list // 여기서 함수 사이클 종료
}

// sequence + yield: 하나 주고 멈추고, 또 달라면 이어서 실행
fun numbers(): Sequence<Int> = sequence {
    yield(1)    // 소비자가 첫 원소를 달라고 하면 여기까지 실행되고 정지
    yield(2)    // 두 번째를 달라고 하면 여기서 재개 -> 2 주고 다시 정리
    yield(3)
}
```

소비하는 객체에서 보면:
```java
val seq = numbers()        // 이 시점엔 블록이 한 줄도 실행 안 됨
val it = seq.iterator()
it.next()  // → 1  (yield(1)까지 실행되고 멈춤)
it.next()  // → 2  (멈췄던 지점부터 재개)
```
그래서 return은 함수가 끝나지만 yield는 지역변수 루프 위치 같은 실행 상태를 전부 보존한 채 잠시 양보만 한다.
이게 가능한 이유는 sequence {} 블록이 사실 kotlin 코루틴(suspend 함수)이기 때문이다.

# yieldAll이란?
Kotiln의 sequence {} 빌더 안에서 쓰는 함수로, 컬렉션(또는 다른 sequence)의 원소들을 통쨰로 시퀸스에 흘려보느내는 역할을 한다.
```java
for (t in tuples) {
    yield(t)
}
```
이때 
1. scan()을 호출해도 아무 일도 일어나지 않는다. -sequence {}는 lazy라서, 소비자가 원소를 꺼낼 때만 블록이 실행된다.
2. 소비자가 첫 원소를 요청하면 페이지 0을 fetch -> 튜플들을 전부 디코딩해 tuples 리스트를 만들고 -> unpin -> yieldAll(tuples)에서 첫 튜플을 내보내고 일시정지한다.
3. 다음 원소를 요청하면 그 정지 지점부터 재개해서 tuples의 두번째 원소를 내보내고, 리스트가 소진되면 다음 페이지 루프로 넘어간다.
