# Any? 
- Kotlin에서 모든 타입의 최상위(Any) + null 허용
"무엇이든, 없을 수도 있다"
```java
abstract fun evaluate(tuple: Tuple): Any? 이
```
Any를 쓰는 경우 대부분 하위 클래스마다 결과 타입이 다르기 때문이다.
하위 클래스
```java
data class ColumnRef(...)  → tuple.get(name)     // 컬럼 타입에 따라 Long · String · Int · null
data class Literal(...)    → value               // 리터럴에 넣은 것 그대로
data class Compare(...)    → Boolean 또는 null   // 비교 결과, NULL 끼면 null
data class Logical(...)    → Boolean 또는 null
```
이와 같이 서로 다른 리턴값을 하나의 시그니처로 다 담을 수 있는 표현은 Any?밖에 없다.
이때 해당 타입은 Object와 같이 컴파일러가 타입을 못잡아준다는 단점이 존재한다.

# Kotlin의 it
it은 Kotlin이 만들어주는 이름이다. 선언할 필요가 없다.
규칙은 단 한줄이다. -> 파라미터가 정확히 하나인 람다에서 이름을 안 붙이면, 컴파일러가 그 파라미터를 it이라 부른다.
```java
childCols.firstOrNull { it.name == name }
// 완전히 같은 코드
childCols.firstOrNull { col -> col.name == name }
```
firstOrNull은 "원소 하나를 받아 Boolean을 내놓는 함수"를 인자로 받는다.
그 원소가 ColumnDef라는 건 childCols의 타입에서 이미 결정되어 있으니, 컴파일러는 it이 ColumnDef인걸 안다.

이때 그럼 중첩 구조에서는 it을 연속으로 안쓰는가?
```java
columnNames.map { name ->                       // ← 여기서 it을 썼다면
    childCols.firstOrNull { it.name == name }   // ← 안쪽 it이 바깥을 가려버린다
}
```
it은 가장 가까운 람다를 가리킨다. 둘 다 it이면 안쪽이 바깥쪽을 가려서(shadowing) 바깥 값을 손댈 방법이 없어진다.
그래서 name을 주는 것이다.
관용은 이렇다. -> 중첩이 없고 한 줄이면 it, 중첩되거나 길어지면 이름을 붙인다. srcTuple이 이름을 가진 것도 같은 이유다.

# 엘비스 연산자 (?:)
왼쪽 ?: 오른쪽
//왼쪽이 null이 아니면 왼쪽, null이면 오른쪽
firstOrNull은 이름 그대로 못 찾으면 null을 돌려주며, 그래서 찾으면 그걸쓰고 없으면 error가 되는 구조,
이때 여기 구조에서 눈여겨볼 건 타입이 어떻게 되느냐이다.
```java
childCols.firstOrNull { ... }              // ColumnDef?  ← null 가능
childCols.firstOrNull { ... } ?: error(…)  // ColumnDef   ← null 아님
```
error()는 IllegalStateException을 던지고 정상적으로 돌아오는 일이 없다.
kotlin은 그런 함수의 반환 타입을 Nothing이라는 특수 타입으로 표시하는 데, 컴파일러는 "오른쪽 가지가 값을 내놓지 않는다"는걸 알기 때문에
전체 식의 타입에서 ?를 때어낸다.
그결과
```java
val keptCols = columnNames.map { ... }   // List<ColumnDef>  — List<ColumnDef?>가 아니다
outputSchema = TableSchema(name = ..., columns = keptCols)
```
위와 같아지며,
TableSchema는 List<ColumnDef>를 받는다. 만약 ?: error(...)가 없으면 타입이 List<ColumnDef?>가 되어 여기서 컴파일이 막힌다.
즉 이 한줄은 예외 처리이면서 동시에 타입을 맞추는 장치가 된다.
- columnNames를 하나씩 돌면서 child 스키마에서 같은 이름의 컬럼을 찾는다. 하나라도 없으면 즉시
  init에서 터뜨리는 것이 핵심이다. 질의를 실행하는 도중이 아니라 연산자를 조립하는 시점에 걸리므로, 100만 행을 흝다가 중간에 죽는 일이 없다.
