# !!는 not-null 단언 연산자
T?를 T로 바꾸고, 실제로 null이면 그 자리에서 NullPointerException을 던진다.
테스트에서는 !!가 적절할 수 있는 이유는 null이 나오면 곧 테스트 실패이고,
요란하게 터지는게 맞기때문이다.
반면 운영코드에서는 안좋을 수 있다.
컴파일러의 null 검사를 "내가 책임진다"로 덮어쓰는 것이라, 틀리면 컴파일러가 막아줬을 오류가
런타임 NPE로 나온다. kotlin이 null 안전을 도입한 이유를 무력화하는것,

# to 메서드
to는 Pair를 만드는 함수
heap to tuple == Pair(heap,tuple)
kotlin 표준 라이브러리 내부
infix fun <A, B> A.to(that: B): Pair<A, B> = Pair(this, that)
위가 처리이며,
infix가 붙어 있어서 heap.to(tuple) 대신 점과 괄호를 생략하고 사용할 수 있다.
해당 함수는 map을 읽기 좋게 만드려고 도입
mapOf("a" to 1, "b" to 2)

private val pending: MutableList<Pair<TableHeap, Tuple>> = mutableListOf()
를 보면

"어느 heap에 어느 tuple을 넣을지"를 한 덩어리로 묶어야 하는데, 그걸 위해 클래스를 하나 만들 것까지는 없어서 Pair를 쓴 것이다.

그리고 꺼낼 때는 구조 분해로 다시 둘로 푼다:

for ((heap, tuple) in pending) heap.insert(tuple)
//   ^^^^^^^^^^^^^^  Pair의 first, second를 각각 이름 붙여 받는다

참고로 Pair가 항상 좋은 선택은 아니다 — 값이 셋 이상이거나 의미가 헷갈릴 때는 first/second가 무엇인지 알 수 없어진다. 그럴 땐 이름 있는 data class를 만드는 편이 낫다. 여기서는 둘뿐이고 바로 옆에서 풀어 쓰므로 Pair로 충분하다.
